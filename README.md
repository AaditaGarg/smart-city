# Smart City Intelligence System

Vehicle detection, congestion estimation, and road-damage detection with a FastAPI + PostgreSQL backend,
a React dashboard, and a rule-based decision engine for repair prioritisation and signal recommendations.

> Status: **Steps 1-4 code complete (training scripts written; results pending your runs).** Results/metrics sections are filled only from real training runs in later steps.

## Prerequisites
Python 3.10-3.12, Node 18+, Docker (for PostgreSQL), VS Code. A GPU is strongly recommended for training (CPU works for small runs).

## Setup
```bash
# 1. Python env
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt    # for GPU torch, install from pytorch.org first

# 2. Config + database
cp .env.example .env               # Windows: copy .env.example .env
docker compose up -d

# 3. Verify
python scripts/verify_setup.py

# 4. Backend
uvicorn backend.app.main:app --reload --port 8000   # http://localhost:8000/docs

# 5. Frontend (new terminal)
cd frontend && npm install && npm run dev            # http://localhost:5173
```

## Layout
```
backend/app/      FastAPI (api/, core/, db/, services/)
ml/               data, preprocessing, training, evaluation, inference
decision_engine/  repair priority + signal recommendation logic
configs/          project.yaml (classes, splits, datasets)
scripts/          setup + dataset download utilities
data/             raw / interim / processed (git-ignored)
models/           trained weights   runs/  training logs
reports/          figures + tables generated by evaluation
frontend/         React (Vite) dashboard
tests/            pytest
```

## Data preparation (Step 3)
```bash
python scripts/download_datasets.py kitti
python scripts/fetch_rdd2022.py --country India
python -m ml.preprocessing.prepare_kitti        # -> data/processed/vehicle/   (+ data.yaml)
python -m ml.preprocessing.prepare_rdd          # -> data/processed/road_damage/
python -m ml.preprocessing.augment --dataset road_damage   # rare-class oversampling, train split only
pytest tests/test_preprocessing.py
```
Outputs: `reports/tables/*_validation_issues.csv`, `*_prep_summary.json`, `*_split_stats.csv`, and
`reports/figures/*_class_distribution.png`, `*_augmentation_examples.png`. All numbers come from the data on disk.

Design notes: only the four official RDD2022 classes are kept (D01->D00, D11->D10 merged; D43/D44/D50 and the
`D0w0` typo dropped; images whose only labels were dropped are excluded as ambiguous). KITTI train+val are pooled
and re-split 70/15/15 (stratified); KITTI frames come from driving sequences, so neighbouring frames may land in
different splits and test scores will be somewhat optimistic.

## Training (Step 4)
```bash
python -m ml.training.train_yolo --task vehicle --quick       # smoke test (5% data, 2 epochs)
python -m ml.training.train_yolo --task vehicle               # full run
python -m ml.training.train_yolo --task road_damage
python -m ml.training.congestion --weights models/vehicle_best.pt
```
Weights go to `models/`, curves/logs to `runs/<task>/`, run metadata (wall time, versions, device) to
`models/<task>_train_meta.json`. Congestion uses a proxy target derived from annotated vehicles (KITTI has no
congestion labels); see the docstring in `ml/training/congestion.py`.
